# API-first GitHub App operation

The GitHub App can authenticate and query GitHub without exposing a webhook listener. The CLI uses the registered App ID and its private key to create installation-scoped clients. It does not generate a public endpoint or invoke any signing/publishing service.

## Configuration
Use `APP_ID=5554493` and `PRIVATE_KEY_PATH=/absolute/path/to/key.pem` in your local shell. Never commit credentials. The webhook secret is **not** needed for CLI operations.

## Read-only commands

```bash
npm ci
npm run build
npm run cli -- installations
npm run cli -- repos --installation 177191086
npm run cli -- runs --installation 177191086 --repo erikg84/apk-signing-poc-app
npm run cli -- artifacts --installation 177191086 --repo erikg84/apk-signing-poc-app --run 41212205303
```

The first command uses GitHub App JWT authentication. The remaining commands use temporary installation access tokens generated by Octokit. Output is limited to metadata; CLI does not download artifact bytes, dispatch workflows, sign APKs, or publish to Artifactory.

## Optional Probot adapter

The Probot webhook handler remains available using `npm start`, but the API CLI doesn't require Probot to be running, a webhook secret, cloudflared, a custom domain, or any inbound network access.

To stop using webhooks, disable deliveries in the GitHub App settings. Do not delete the App or revoke its private key: those credentials enable the API-only path. Cloudflare tunnel services can be stopped by the local operator after confirming they're no longer used.

## Verified (2026-10-31)

With Probot and the Cloudflare Quick Tunnel both stopped and no `WEBHOOK_SECRET` set, all four commands were run against the real registered App (`5554493`) and installation (`177191086`) and returned correct, live GitHub data — see `docs/VALIDATION.md` for the full output. This confirms the API-first path has no dependency on the webhook listener, tunnel, or secret.

## Future contract

A separate signing service may accept a workflow run ID, repository ID, and installation context, and must independently verify authorization and artifact provenance. Do not transfer APK-specific policy into this general-purpose GitHub integration repository.
